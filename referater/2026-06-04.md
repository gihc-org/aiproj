## Beslutninger truffet

- **LLM-review frem for syntaktiske checks.** Syntaktiske checks (grep-mønstre, fil-eksistens) er sprog-specifikke og har ingen semantisk forbindelse til ADR-teksten. En LLM der får både diff og guideline-indhold kan vurdere intent, ikke blot struktur.
- **Raw `.git/hooks/pre-commit` frem for pre-commit-framework.** Simplere, ingen afhængigheder, lettere at forstå og migrere.
- **Fail open ved utilgængeligt LLM.** Manglende netværk eller `claude`-installation blokerer ikke udvikling — commit advares men tillades.
- **Hard exit 1 ved concerns — ingen `commit anyway?`-prompt.** Agenter ser fejlbeskeden og retter koden; mennesker kan bruge `--no-verify` bevidst.
- **check.sh er projektets eget.** Scriptet kopieres ind i hvert projekt og kan tilpasses per projekt. Ingen central kobling til aiproj-stien.
- **Section headers i shell-scripts er tilladt.** Claude flaged `# ── Konfiguration ──` som "hvad"-kommentar. Vi var uenige — de er navigation, ikke forklaring. Guideline opdateret.
- **Tests for check.sh udeladt.** Shell-script unit-tests via bats estimeret til en halv dag. Den interessante logik (om Claude finder den rigtige overtrædelse) kan ikke testes automatisk. Accepteret som bevidst fravalg.

## Nøgleindsigt

Syntaktisk håndhævelse (tjek om testfiler er rørt) er sprog-specifik og semantisk tom. Den kan ikke se om ADR-0007's krav om log-sanitering er overholdt — kun at `auth.rs` er ændret. LLM-review løser begge problemer på én gang: det er sprog-agnostisk og forstår intent.

`.guidelines/` i eksisterende projekter er symlinks til `~/projects/guidelines/` — ikke kopier. Guideline-opdateringer er derfor øjeblikkeligt synlige i alle projekter uden synkronisering.

## Åbne tråde / næste skridt

- **Sektion 1** — frontmatter-format og `tool-neutral-enforcement.md` ikke skrevet endnu.
- **Sektion 2** — frontmatter + selector-script ikke påbegyndt. Brugeren vil have det til at gøre det lettere at finde relevante ADRs/guidelines ved oprettelse af AGENTS.md.
- **Sektion 3** — gennemgang af eksisterende guidelines og ADRs for projektspecifikke detaljer ikke påbegyndt.
- **Sektion 5** — øvrige projekter (yargent, score, sso-gihc, cved) ikke migreret endnu.
- **Konfigurérbar LLM-kommando** — i dag hardcoded til `claude`. Ønskes konfigurerbar på sigt.
- **CI som andet lag** — hook kan omgås med `--no-verify`. CI-check af samme review ikke implementeret.

## Gotchas

- `install-hooks.sh` antog i første version at `check.sh` allerede lå i målprojektet — rettet til at kopiere scriptet selv.
- `.guidelines/` i ipfs-apps er et symlink, ikke en kopi. Forsøg på at `cp` opdateret guideline dertil var unødvendigt og blev afbrudt af brugeren.
- `claude --print` modtager prompt som shell-argument. Meget lange prompts (stor diff + mange ADRs) kan i teorien ramme shell-argumentlængregrænser. Bruger temp-fil som buffer.
